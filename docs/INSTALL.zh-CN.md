# LD14 信号量泄漏临时修补 0.1.0-alpha.1

这是一份可审阅源码的本地临时修补，不是雷电官方补丁。

项目仓库：<https://github.com/Yuiffy/ldplayer14-community-fix>。
下载预发布包：<https://github.com/Yuiffy/ldplayer14-community-fix/releases>。

**已验证修复：渲染线程析构时漏关一个信号量。尚未修复：长期运行时的大额私有内存增长。黑屏问题也不能据此认定已解决。** 分享时请保留这一说明。

## 适用范围

- Windows 64 位，雷电 14.0.26.1 或 14.0.31.0 的指定文件配对，已验证共享后端版本 6.1.50.161033。
- 必须匹配下方列出的渲染器和 LD14 fastpipe 文件 SHA256。版本号相同也不代表文件一定相同。
- 需要 64 位 Python 3.10 或更新版本，以及 `py.exe` Python Launcher。
- Python 官方下载：<https://www.python.org/downloads/windows/>。安装时包括 Python Launcher；脚本只用 Python 标准库，无额外依赖。

仅修改选定 LD14 实例当前进程中的少量机器码。重启进程后失效。包内不含雷电 DLL、显卡 DLL、个人配置或诊断内存转储。

## 首次配置

1. 解压整个 ZIP 到一个长期保留、当前用户可写的本地文件夹，例如 `D:\Tools\LD14-Fix`。不要直接在 ZIP 中运行。
2. 双击 `Setup-LD14-Fix.cmd`。
3. 输入自己的雷电 14 安装目录，或该目录下 `ldconsole.exe` 的完整路径。目录名可以包含空格或中文。
4. 在列出的实例中，输入要修补的实例编号。编号来自多开实例列表，不保证为 0 或 1；按自己的实例名称选择。
5. 显示 `Saved local configuration` 即完成。配置保存在本机的 `ld14-fix.config.json`，不要把自己的配置文件加入分享包。

配置过程不会修改渲染器或启动游戏。若报告 `Unsupported LD14 installation`，表示本机文件不是已经验证的版本，应停止使用本版修补。

## 日常启动

双击 `Start-LD14-Fixed.cmd`。如果选定的实例没有运行，脚本会启动它，然后等待渲染器加载并应用补丁；如果已经运行，则核对并修补当前实例。

每次重新启动 LD14，都需要通过这个入口应用补丁。从雷电原来的入口启动不会自动带上补丁。无需复制或覆盖雷电的任何程序文件。

成功时输出中会有：

```json
{
  "before": "original",
  "after": "patched"
}
```

已经修补过时，`before` 和 `after` 都是 `patched`，不会重复写入。应用记录保存在同目录 `logs` 文件夹。

## 验证和长时间观察

双击 `Check-LD14-Fix.cmd`，会显示当前补丁状态、PID、私有提交、工作集和句柄数，并保存 JSON 记录。

挂机比较建议：

1. 用修补启动器打开 LD14，再按平时方式运行《碧蓝航线》或原本触发问题的应用。
2. 等游戏完成加载和预热约 10 分钟，双击 `Record-LD14-Stats.cmd`。
3. 它每分钟记录一次，默认持续 4 小时。先看 30-60 分钟，再比较 2-4 小时；不必等内存累计到几十 GiB。
4. `logs\ld14-stats-时间.csv` 包含时间、PID、补丁状态、私有提交、工作集和句柄。可按 Ctrl+C 提前停止，已记录的数据会保留。
5. 记下这段时间游戏处于战斗、挂机、登录或关闭状态，以及是否发生卡顿、重启或黑屏。单纯比较安卓桌面和游戏加载后的内存会混入正常负载差异。

记录工具只读取数据，不会重启模拟器、清理内存或应用补丁。模拟器退出或 PID 改变时停止本次记录，避免混用两次运行的数据。运行记录工具时保留其窗口。

句柄稳定只能验证这一处漏关被抑制，不能证明内存泄漏已消失。发现私有提交仍持续明显上涨或重现黑屏时，应保存记录继续定位。

## 卸载与回退

正常退出 LD14，再从雷电原来的入口启动，即回到原始代码。无需还原 DLL。停止记录工具后，可以删除本修补文件夹。

本工具不创建服务、计划任务或开机启动项。修补前已经泄漏的旧句柄不会被盲目关闭；正常重启实例才能释放这些残留。

## 常见情况

- 提示缺少 Python：安装官方 64 位 Python 和 Launcher。也可用已安装的 64 位 `python.exe` 手动运行下方命令。
- `Access is denied` / WinError 5：检查模拟器是否以管理员权限运行。如是，请让修补启动器以相同权限运行。
- `Unsupported renderer version`：渲染器 SHA256 不符，脚本没有应用补丁。不要绕过校验。
- `Unexpected function entry`：可能存在其他修补或诊断探针。先正常重启 LD14，再核对版本。
- 配置错实例：重新运行 `Setup-LD14-Fix.cmd`。同一文件夹一次保存一个实例的配置；多个实例可各用一份文件夹。
- 更新雷电后：重新核对文件版本。本包只验证下列文件，不承诺兼容未来更新。

## 命令行

在解压目录打开 PowerShell，按自己的路径和实例编号运行：

```powershell
py -3 .\ld14-local-fix.py --setup --console 'D:\LDPlayer\LDPlayer14\ldconsole.exe' --index 0
py -3 .\ld14-local-fix.py --start
py -3 .\ld14-local-fix.py --check --save
py -3 .\ld14-local-fix.py --monitor --minutes 120 --interval 60
```

`--check` 为默认只读动作。`--apply` 仅修补已经运行的配置实例；`--list` 列出实例。命令行也接受 `--console` 和 `--index` 临时覆盖本机配置。

没有 `py.exe` 时，把 `py -3` 换成 `& '你的64位Python完整路径\python.exe'`。

## 修补原理和验证

构造函数为每个 `MyRenderThread` 创建两个信号量，存放在对象 `+0x4b8`、`+0x4c0`。原析构函数只关闭后一个。修补增加前一个信号量的 `CloseHandle`，保留原有清理顺序。

14.0.26.1 的三个修改位置为渲染器 RVA `0x609e2`、`0x60a71`、`0x60aff`，14.0.31.0 为 `0x60b62`、`0x60bf1`、`0x60c7f`；各自前两个位置使用同一析构函数内部不可达的对齐空间。按完整文件哈希选择对应配置，不根据版本号推算偏移。修改时短暂挂起选定进程，写入后核对结果、恢复代码页权限，并恢复进程运行。

验证结果：128 个原始机器码案例复现漏关，128 个修补案例全部关闭预期句柄；实时运行记录到 325 次析构、650 次信号量创建和 650 次关闭；Android 离屏 EGL 30 轮像素及资源生命周期检查通过。

然而，修补后游戏实际运行仍曾在约 70 秒内增加 334.98 MiB 私有提交，所以这不是完整的内存泄漏修复。
