# LD14 14.0.32.1 本地适配

2026-10-31，LD14 更新到 `14.0.32.1` 后，LD9 与 LD14 的后端都加载了共享的
`C:\Program Files\ldplayer9box\libOpenglRender2.dll`。旧守护因未知 renderer 哈希拒绝应用补丁。

本次现场采样得到的完整文件配对为：

| 文件 | SHA256 |
|---|---|
| renderer（LD14 `vbox64` 与共享目录相同） | `ed56d3dfc77b4c3903abb38eee14f24842dfdfebb7c0a85da5a4f6b64600426d` |
| LD14 `gpu/fastpipe2.dll` | `ecbb6fab5fcfac9d5467c174b9ffc45bb985e5e520a1e90e1a66d950e540ddd3` |

## 结构检查

- renderer 为 PE x64，大小 `11746784` 字节；`.text`、`.rdata`、`.data` 和 `.pdata`
  的布局与 14.0.31.0 适配使用的布局一致。
- 14.0.31.0 配置的三个原始补丁片段在新文件中逐字节匹配：
  `0x60b62`、`0x60bf1`、`0x60c7f`。
- 三个运行时保护片段也逐字节匹配：`0x60b10`、`0x60660`、`0x60c6f`。
- 当前 LD14 后端实际加载的是上述 `gpu/fastpipe2.dll`，不是 LD9 的 fastpipe 文件。

因此 14.0.32.1 复用 14.0.31.0 的机器码布局和补丁字节，但仍通过独立的完整 SHA256
配对选择 profile。未知或混配文件继续拒绝应用。

## 限制

这证明补丁可以安全定位到当前二进制的同一代码位置，不等于已经证明长期私有提交增长或黑屏问题解决。更新后首次运行仍需检查守护状态为 `active`、
`semaphore_patch: patched`，并继续记录内存、句柄和黑屏事件。
