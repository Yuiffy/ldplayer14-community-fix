# NVIDIA 616.92 适配与验证

2026-09-19，Windows x64、RTX 5080、LD14 14.0.26.1、Frida 17.17.0。

升级显卡驱动后，旧控制器因 SHA256 不匹配拒绝应用。616.92 的实际模拟器负载仍然复现“TLS 回调清理线程堆后，驱动 DllMain 又创建新堆，退出时留下空页”的问题。本次为新版 DLL 增加独立地址配置，保留原 616.64 配置和未知文件拒绝机制。

## 地址与结构确认

| 位置 | 616.64 RVA | 616.92 RVA |
| --- | --- | --- |
| DLL 入口 | `0x107d678` | `0x107d828` |
| TLS 索引 | `0x2d424e8` | `0x2d554e8` |
| 当前 TEB 函数 | `0xa7f440` | `0xa7f440` |
| mimalloc 线程清理 | `0xa7f2d0` | `0xa7f2d0` |
| 空堆 | `0x1af4a00` | `0x1af4a00` |
| 静态主堆 | `0x2c3af00` | `0x2c4df00` |

完整文件哈希列于[运行条件](../experimental/README.zh-CN.md#运行条件)。两个版本的 PE 入口、PE TLS 索引及六处代码检查均与各自文件吻合。没有用版本字符串替代 SHA256。

离线比较中，排除相对地址编码后，完整 354 字节线程清理路径、DLL 入口、DllMain、TLS 回调、线程初始化与相关堆清理路径均能对应。运行时探针继续按 TEB、TLD 序号和 backing heap 联合验证所有权；只比较地址不足以排除内存重用。

生产代码不扫描未知驱动来猜测地址。Python 从两个明确允许的哈希中选择配置，检查目标进程的原始指令，再把这同一份配置传给原生回调。新添加的检查还覆盖 TLS 索引、空堆和主堆的指令引用。原生回调仍只清理当前退出线程自己的普通 backing heap，不处理历史遗留地址，也不修改磁盘驱动文件。

## 运行验证

先在独立 WGL 子进程中跟踪 12 轮上下文创建/绘制/退出，得到 480 条事件，无丢失，正常结束。

随后在同一 LD14 进程中运行 Android EGL 离屏测试。各组都保留信号量修补，每组创建 12 个绘制线程；测量仅针对本轮新建的线程堆。B 组使用仓库实际交付的 `nvidia-thread-cleanup.js` 及新的驱动配置。

| 对照 | 新残留线程堆 | 所持页数 | 完全空闲的页 | 像素检查 |
| --- | ---: | ---: | ---: | ---: |
| A：原始驱动清理 | 13 | 270 | 15.875 MiB | 12/12 |
| B：启用新版补充清理 | 0 | 0 | 0 | 12/12 |
| A：撤回补充清理 | 13 | 272 | 15.6875 MiB | 12/12 |

三组都观察到 13 次在驱动线程退出 DllMain 内创建 TLD。B 组记录 27 次线程退出、13 次补充清理，`owner_mismatch` 与 `cleanup_still_owned` 都为 0。三组堆/页结构校验、远程释放链检查和跟踪事件均无错误或丢失。B 组与回退组结束后，实时指令检查确认 hook 已撤回。

27 个回归测试通过，包含两个驱动配置各自的九种原生所有权/退出情形、返回值保持、入口恢复、未知哈希拒绝、运行中 TLS 引用被改动时拒绝，以及无限期守护生命周期。厂商文件、完整跟踪和转储未提交；脱敏汇总见 [validation-20260919.json](../experimental/validation-20260919.json)。

## 更新与限制

更新完整仓库后运行 `Start-LD14-Guard.cmd`。新版标记 `LD14-DUAL-FIX-GUARD-4` 会让启动器正常替换旧控制器。实例运行时，状态应同时显示：

```text
state: active
driver_version: 616.92
semaphore_patch: patched
nvidia_cleanup: true
frida_usb_guard.active: true
```

控制器更新本身不需要重启模拟器。若模拟器没有启动，守护会显示 `waiting_for_ld14`，并在下次启动后应用。驱动安装期间已经失效的图形上下文则属于另一种情况，应在更新完成后重新启动受影响的应用。

616.92 的短时对照验证不等于长期游戏测试完成，也不证明整个模拟器没有其他内存增长。此前 616.64 在五天多运行中已抑制几十 GiB 的暴涨，但仍观察到约 0.4 GiB/天的缓慢增长；此处补丁没有针对那部分尚未归属的增长增加额外释放。新驱动需要继续观察相同游戏负载下的曲线。

此次适配不包含显示器黑屏修复，不改变显卡超时或电源设置。
